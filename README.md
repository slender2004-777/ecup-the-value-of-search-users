# Прогнозирование 30-дневного LTV пользователей по разреженным логам активности

Сквозной ML-пайплайн, предсказывающий суммарный GMV каждого пользователя за
следующие 30 дней по 13 месяцам дневных логов. Данные: 250 000 пользователей,
~30 млн строк, 18 поведенческих метрик на пользователя-день (поиск, каталог,
корзина, заказы, GMV). Итоговый RMSLE на публичном лидерборде — **1.676**
(наивный бейзлайн ≈ 2.24, ошибка снижена примерно на 25%).

Каждое проектное решение проверялось offline на time-based
кросс-валидации, а немногочисленные живые отправки использовались как
спланированные калибровочные эксперименты, а не как перебор.

## Постановка задачи

Даны дневные сводки активности пользователей с 2025-01-01 по 2026-02-13
(строки есть только в дни активности — ряды имеют пропуски, полное заполнение
нулями раздула бы данные до 100 млн строк). Нужно предсказать суммарный GMV
каждого из 250 000 пользователей на горизонте 30 дней от финального среза.
Метрика — RMSLE c `log1p`:

$$
\text{RMSLE} = \sqrt{\, \text{mean}\!\left( \left( \log(1 + y_{\text{true}}) - \log(1 + y_{\text{pred}}) \right)^2 \right) }
$$

При такой метрике оптимальный точечный прогноз — `expm1(E[log1p(y)])`, что
сразу диктует обучение одной регрессии на `log1p(таргет)` с квадратичной
функцией потерь.

## Ключевые решения и находки

1. **Популяция оценивания задаётся свежестью.** EDA показал: 100%
   оцениваемых пользователей активны в последние 30 дней до среза (69% — в
   последние 3 дня). Поэтому вся валидация считалась на соответствующей
   «test-like» подвыборке, а не на всех пользователях — это меняет величину
   метрики на ~0.02.
2. **~46% таргетов — точные нули**, а `P(таргет > 0)` плавно падает с
   прошествием дней с последней покупки (0.61 при 0–3 днях → 0.24 при
   15–30). Recency-фичи стали признаками первого порядка.
3. **Выравнивание таргета под метрику.** При RMSLE оптимальный точечный
   прогноз — `expm1(E[log1p(y)])`, поэтому одна GBDT-регрессия на
   `log1p(таргет)` с квадратичной функцией потерь — теоретически правильный
   выбор. Двухэтапная схема (классификатор покупки × регрессор на позитивах)
   была проверена и выигрыша не дала (1.816 против 1.814 по CV).
4. **YoY-бленд.** Финальный лог-прогноз = `0.85·модель + 0.15·log1p(GMV
   того же календарного окна год назад)` — даёт ~0.012 RMSLE (подтверждено
   на лидерборде). Это работает, потому что год-назад-окно несёт сигнал о
   индивидуальной сезонности пользователя, которого нет в оконных признаках.
5. **Сезонная гипотеза — предложена, проверена, опровергнута.** Целевое
   окно захватывает два «подарочных» праздника, анализ на уровне платформы
   давал сезонный аплифт ×1.16 (двумя независимыми способами), offline-эксперименты
   поддерживали мультипликативную поправку. Но три специально спроектированные
   проверочные отправки её опровергли: квадратичный фит `RMSLE²(ln k)` дал
   оптимум `k* = 0.81`, то есть модель *завышала* прогноз. Урок: CV
   валидирует механизм, но не знак распределённого сдвига. Кривая — на
   рисунке `reports/figures/calibration_curve.png`.

## Архитектура решения

1. **Панель признаков по временным срезам.** Для каждого среза (12 в
   пайплайне, ~49 в плотной панели) каждый пользователь — одна обучающая
   строка: ~250 признаков, посчитанных строго по данным до среза; таргет —
   GMV за следующие 30 дней.
2. **Честная time-CV с гэпом 31 день.** Обучающие фолды строго раньше
   валидационного; фолд для early stopping исключён из обучения; гэп 31 день
   исключает пересечение таргет-окон train/valid.
3. **Признаки (~250):** суммы/счётчики по окнам 3/7/14/30/60/90/180/365/вся
   история для всех метрик (raw + `log1p`), дни-с-событиями, экспоненциально
   взвешенная активность (EMA с периодами полураспада 7–90), пять
   recency-переменных, tenure, отношения интенсивностей (прокси тренда),
   конверсия и AOV, доли каналов (поиск/каталог), календарные признаки
   (месяц, день недели, Фурье-члены дня года), год-к-году признаки там, где
   календарное окно есть в истории.
4. **Ансамбль LightGBM + XGBoost** на `log1p(таргет)`, с весами,
   подобранными на валидации (XGBoost стабильно немного сильнее),
   усреднение по сидам в финале. CatBoost проверялся и отброшен (уступал
   > 0.01 RMSLE по CV).
5. **Пост-обработка.**
   - *YoY-бленд:* финальный лог-прогноз = `z·модель + (1-z)·log1p(GMV год
     назад)`, `z` подбирается на валидации.
   - *Глобальная мультипликативная калибровка:* при `RMSLE²(ln k) ≈
     параболе` три проверочные отправки с разными множителями однозначно
     находят оптимум; кривая у вершины плоская (`k ∈ [0.75, 0.87]` в
     пределах 0.001), что делает калибровку устойчивой к смене выборки.

## Результаты

| Подход | CV RMSLE (test-like) | Лидерборд |
|---|---|---|
| Наивный: GMV | 2.24 | — |
| Лучшая эвристика (взвешенные оконные средние + YoY) | 1.98 | — |
| Одна LightGBM на базовых признаках | 1.74 | — |
| **Полный пайплайн (этот репозиторий)** | **1.70** | **1.676** |

## Воспроизведение

```bash
pip install -r requirements.txt
# положить train.parquet и sample_submit.csv в data/ (не распространяются)
python src/01_eda.py
python src/02_pipeline.py
python src/03_dense_panel.py
python make_figures.py
# опционально: калибровка после получения public-скоров
python src/04_calibration.py fit
```

Все артефакты (отчёты, CSV, сабмиты) пишутся в `out/`; графики — в
`reports/figures/`. Каталог `out/` git-ignored.

## Потенциально можно улучшить

- **Сегментная калибровка** — множитель по децилям активности. Плоский
  глобальный оптимум намекает на запас «на хвостах»: тяжёлые пользователи
  могут требовать другого множителя, чем лёгкие.
- **Секвенсные модели** по токенизированному дневному поведению — панель
  естественно выравнивается под последовательности дней, это должно дать
  сигнал о порядке событий, который оконные суммы теряют.
- **Survival-компонента** — стекинг GBDT-панели с survival-моделью
  затухания для нулевой компоненты таргета. Сейчас 46% нулей обрабатываются
  только через recency-фичи, явная модель «вернётся / не вернётся» должна
  помочь.
- **Квантильные цели / CRPS** — страховка от сдвига между выборками.
  Точечный прогноз `expm1(E[log1p(y)])` оптимален при совпадении
  распределений, но калибровка на лидерборде показала, что знак сдвига
  угадать нельзя — квантильная модель дала бы робастную оценку.
